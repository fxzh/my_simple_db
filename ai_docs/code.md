# 编写代码要求

本文件为工程通用编写要求，开始编码前通读。修改完成后，总结末尾必须附"规则自检清单"，逐条声明
本次改动所涉规则的遵守/违反情况(未涉及项写"未涉及")；未列入清单的违规项一律视为对规则的违反。
如果未修改仓库内容，总结时无需附此"规则自检清单"

代码要求：
使用 c++20 进行编写，如果编写时发现必须使用c语言，需要在总结时说明原因
在行宽<=100列时禁止换行, >100列时可考虑换行, 也可不换行
预期外状态的唯一处理方式是立刻报错, 禁止静默降级，包括 return 0/false/空值当作无操作、跳过继续、返回默认值、退到备用实现(fallback)，确需容忍某状态时，必须在总结中说明其触发场景

结构体要求：使用 struct 而不是 class, 直接访问结构体成员而不是通过一个函数间接访问

日志要求：所有代码在 报critical/报error/报warning/报其他等级日志 时，必须使用 LOG/LOGCPP/LOG_*/DB_RAISE/DB_CRITICAL 宏，禁止直接throw std::runtime_error, _exit等行为（client代码，tool代码除外），如确实不能使用这些宏，必须在总结时说明

报错要求：
有错立刻就报，禁止储存错误信息延后报错，如确实需要延后报错设计，必须在总结时说明
DB_RAISE 仅用于回滚当前语句后系统可安全继续服务的错误, 否则, 使用 DB_CRITICAL

修改要求：已有文件一律局部编辑，禁止整文件重写；只动与本次改动直接相关的行，不重排 include 与声明顺序，不动空行/缩进，保留文件原有末尾换行

注释要求：
使用中文, 必须简洁
只描述紧邻代码当前实际执行的行为
禁止引用外部设计文档
禁止状态汇报式写法
禁止写入修改原因与修改经过
禁止写入未实现的,假设性的语句

CMakeLists注释要求: 禁止写入 a依赖b, c链接d, e引用f 这样的注释，如果原先存在这样的注释，修改时需要顺手删除，禁止状态汇报式写法

CLAUDE.md修改要求：使用中文，简洁，禁止状态汇报式写法，禁止写入"不做什么"，只保留代码+注释里读不出来的信息：设计决策、跨模块约定、已知坑；修改时，如发现该CLAUDE.md的某条信息已经可以从代码里读出来，需要将其删除；如需修改开头，限定在一句话以内

修改完成后无需git commit，除非用户要求
