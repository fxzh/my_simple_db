# 测试用例编写要求

如果实现的是某个完整功能的其中一部分，导致不能使用sql用例测试，不编写测试用例，留到实现完整功能时编写

如果实现的是工具功能，编写非sql测试用例，并在总结时进行说明，由用户确定是否保留新增的非sql测试用例

测试用例以正常功能测试为主，加必要的异常场景测试，非sql用例的异常场景测试优先做成独立用例

（可选）如果需要更多的异常场景测试来验证，可在远端进行手动测试，不落入测试代码

如果添加的是sql用例，编写用例的sql文件必须以LF作为换行，out预期文件不臆测，从远端实际执行结果获取，并自行判断实际执行结果是否正确，实际输出与功能预期语义不符时，先定位是实现 bug 还是用例问题，禁止直接写入out预期文件。未授权连接远端时，out预期文件留空并在总结时说明

每一个sql用例需要自行管理一切持久化对象的生命周期，不依赖其他用例遗留的持久化对象，也不遗留持久化对象给其他用例

验证时仅需验证与自身修改相关的用例（节约验证时间），当用例fail且与自身修改无关时，再向上验证更基础的用例

新sql功能如符合某一目录下的表述，在该目录下添加sql用例；否则新建目录，目录名用功能名，并主动更新 test/e2e/sql/CLAUDE.md 文件
