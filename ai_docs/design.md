# 设计方案要求

开始设计前通读。设计完成后，总结末尾必须附"规则自检清单"，逐条声明
本次改动所涉规则的遵守/违反情况(未涉及项写"未涉及")；未列入清单的违规项一律视为对规则的违反。

不考虑前向兼容

遵循标准sql行为，如果因前置功能未实现等原因做不到，总结时说明原因

尽可能规避 fallback 设计，如果无法规避，停下设计并向用户说明原因

如果设计方案会改变src模块依赖关系，需要在总结时说明

如果设计方案时读取了测试用例，不要被已存在的测试用例与输出预期而限制住更好的设计，如果一个更好的设计的代价是修改预期/删除用例，尽管提出来

离线友好，禁止构建期联网下载与自动安装；依赖用系统包，缺失直接报错并提示装什么

如输出设计文档，不要重复说明已有的通用文档的规范（例如 ai_docs 目录下的md文档）
